couchdb-web-node-plugin

A couchdb server, model instance conflict handler, rest api, authentication, session management, schema validator and model relation guarantee for webNode.

src.zip app.zip en de fr

Project status

Use case

This web-node plugin runs a CouchDB compatible database server and connects your application via PouchDB. You describe your data model in the configuration. The plugin turns it into server side validation, so every write is checked no matter which client sends it.

Features included:

  • Starts CouchDB, "pouchdb-server" or an in-process "express-pouchdb", whichever is available.
  • Declarative model specification with types, constraints, defaults, computed values, inheritance and attachments.
  • Role based read and write permissions per model and property.
  • Automatic setup of admin, users, security settings and indexes.
  • Foreign keys between documents and materialized views.
  • Migration of existing documents when the model changes.
  • Changes stream with hooks and automatic restart on failures.

Installation

Install the plugin next to web-node. web-node discovers every installed package whose name ends with "-web-node-plugin" automatically:

yarn add web-node couchdb-web-node-plugin

You also need one database server. The plugin uses the first one it finds in this order:

  1. CouchDB installed on the system at "/usr/lib/couchdb/bin/couchdb".
  2. "pouchdb-server" installed as dependency.
  3. "express" and "express-pouchdb" installed as dependencies, running inside your application process.
yarn add pouchdb-server
# or
yarn add express express-pouchdb

Configuration

All options live below "webNode.couchdb" in your application's "package.json". The most important ones:

{
    "webNode": {
        "couchdb": {
            "admin": {"name": "admin", "password": "change-me"},
            "databaseName": "main",
            "path": "database",
            "runner": {"host": "127.0.0.1", "port": 5984},
            "users": [
                {"name": "editor", "password": "secret", "roles": ["editor"]}
            ]
        }
    }
}
  • "admin": Database administrator, created if missing. Defaults to "admin" with password "admin", so change it for anything public.
  • "users": Additional users with their roles, created if missing.
  • "databaseName": Name of the application database. Defaults to "main".
  • "path": Directory holding the database files. Defaults to "database".
  • "runner.host" and "runner.port": Address of the database server. Default to "0.0.0.0" and "5984".
  • "security": Admin and member roles per database.
  • "model": The data model, see below.

Data model

Models live below "model.entities". Public model names start with an upper case letter, names starting with "_" are abstract models to inherit from. Every model inherits from "_base", which adds the type property "-type". A document's "-type" selects the model it is validated against:

{
    "webNode": {
        "couchdb": {
            "model": {
                "entities": {
                    "Author": {
                        "_extends": "_timeTrackable",
                        "_roles": {"read": ["editor", "reader"], "write": ["editor"]},
                        "name": {
                            "maximumLength": 100,
                            "minimumLength": 1,
                            "nullable": false
                        }
                    },
                    "Book": {
                        "author": {"type": "foreignKey:Author"},
                        "genre": {"selection": ["novel", "poetry"]},
                        "pages": {"minimum": 1, "type": "integer"},
                        "title": {"index": true, "nullable": false}
                    }
                }
            }
        }
    }
}

await services.couchdb.connection.put({
    _id: 'dune',
    '-type': 'Book',
    title: 'Dune',
    pages: 412
})

Frequently used property options:

  • "type": "string" (default), "number", "integer", "boolean", "DateTime", another model name or "foreignKey:<Model>".
  • "nullable", "mutable", "writable", "default": Presence and mutability.
  • "minimum", "maximum", "minimumLength", "maximumLength", "pattern", "selection": Value constraints.
  • "constraintExpression", "createExpression", "updateExpression": JavaScript expressions to validate or compute values.
  • "roles": Read and write permissions for a single property.
  • "index": Creates a database index for the property.

The predefined abstract models "_timeTrackable" (creation and update time), "_userTrackable" (last editing user), "_interval" and "_location" can be extended via "_extends". JSON files in the folder "migration" are written to the database on startup, e.g. to provide initial documents.

Foreign key management

The plugin provides a foreign key management for PouchDB. It allows to define foreign keys in the model specification and automatically checks the existence of the referenced documents when creating or updating documents. It also provides a way to automatically delete or update the referenced documents when the referencing document is deleted or updated.

Initialization

During application start the plugin analyzes the model specification and creates a map of model types to properties that are defined as foreign keys and which model type they reference.

It then goes through all documents having referencing properties and checks if the referenced documents exist. If not, it deletes the reference and if yes, it stores the reference in an internal map of referenced documents to referencing documents.

Document creation and update

When creating or updating a document, the plugin checks if the document has referencing properties. If yes, it checks if the referenced documents exist. If not, it deletes the reference and if yes, it stores the reference in the internal map of referenced documents to referencing documents. It also removes references from the internal map if they are no longer present.

Hooks and services

  • "services.couchdb.connection": PouchDB connection to the application database.
  • "services.couchdb.validateDocument": Validates a document against the model without writing it.
  • "services.couchdb.server.restart": Restarts the database server.
  • "couchdbChange": Hook called for each change in the database.
  • "couchdbInitializeChangesStream": Hook called after the changes stream was (re)initialized.
  • "restartCouchdb": Hook called after each database restart.
  • "initializeExpressPouchDB" and "onPouchDBFind": Hooks to extend the in-process "express-pouchdb" server.
